What changed in the CLI and auto layout

The CLI started as bpmn-io/bpmn-js-cli 2.4.0 plus 17 commands for Zeebe extensions, element templates, annotations and waypoints, and a headless runner. After each iteration I changed it based on what that iteration's runs showed. Per-iteration results are in the appendix.

  1. Iteration 2, layout commands. replace expands a sub-process in place, annotate keeps the width and height it is given, and waypoints routes a flow.
  2. Iteration 3, less lookup. help <command> prints a command's arguments and options, template-props takes --filter and --condensed to shrink the AI Agent template's 150 properties, the README documents every option, and append and connect take an optional flow id.
  3. Iteration 4, one note. Template help and the condensed listing say that omitted properties keep their default. Scripts then set 2 to 3 default-valued properties instead of 12 to 13.
  4. Iteration 5, auto layout. The runner's --autolayout lays the diagram out with bpmn-auto-layout 1.3.0, unmodified, and cli.afterLayout runs callbacks afterwards.
  5. Iteration 6, tidying the library's output. On its own, bpmn-auto-layout drops text annotations, stacks the unconnected children of a sub-process in one column, and routes a loop-back through the diagram. The runner now puts those children in a grid and fits the sub-process around them, shifts later nodes right, centers the sub-process on the main row, routes loop-backs below the diagram and puts annotations back in free space. These are general rules with no coordinates taken from the blueprint.

bpmn-auto-layout itself was not forked or changed, and no upstream issue is filed yet. The three gaps are behaviours seen in its output, not traced in its source. Not every change helped: iteration 4 matched the blueprint less closely than iteration 3 (see the appendix).

Notes

  • Where points were lost. All six runs share some differences from the blueprint: template defaults it lacks (followRedirects, documentReturnFormat, reasoning effort), ignoreNullValues on the GET tools, which template v18 does not offer, and FEEL written without parentheses. Other misses are method-specific: the four Python and /camunda-bpmn runs lack the agentDefinition element, which c8ctl v4.0.0 drops when it applies the AI Agent template (fixed in camunda/c8ctl#574), and the CLI runs have it. Shape positions differ from the blueprint by 89 to 178 px.
  • What the layout score shows. Both CLI runs score the same layout (9.5 of 15) because the auto layout is deterministic, so the score says little about the agent. It also measures how close shapes sit to the blueprint's positions, not overlaps or readability.
  • CLI gap the agents reported. With auto layout the tools are placed in creation order, so cli12 reordered its tool calls to get the left and right columns the spec asks for. Annotation 3 sits above the agent rather than below the user task.
  • Method. Closeness is an F1 over facts from both files, weighted structure 25, configuration 50, annotations 10, layout 15. Cost is estimated at Claude Sonnet 5.5 API rates from the pricing page on 16 October 2026: $2 per million input tokens, $2.50 per million 5-minute cache-write tokens, $0.10 per million cache-read tokens and $10 per million output tokens. Input, cache-write and cache-read counts come from the run transcripts. Those record placeholder output counts, so output tokens are estimated from each run's model time at the rate measured on file writes (about 65 tokens per second, including reasoning), and output is roughly 10 to 15% of each estimate. Cache writes are the largest part (about $0.29 to $0.35 per run), and about 80,000 tokens of them are the fixed agent start-up context that nearly every run pays. The estimate assumes 5-minute caching, which the transcripts show, and ignores any discounts. It excludes the orchestrating main thread and the one-time cost of building the CLI. Sensitivity: if cache reads cost $0.20 per million tokens (the rate in an older cached rate table, and the Sonnet 5 rate) the CLI is {{ALT_H}}% cheaper than /camunda-bpmn and {{ALT_P}}% cheaper than Python. If output tokens were half or double my estimate, the CLI stays {{OUT_H_LO}} to {{OUT_H_HI}}% cheaper than /camunda-bpmn and {{OUT_P_LO}} to {{OUT_P_HI}}% cheaper than Python.
  • The fork is branch camunda-executable of the private repo HanselIdes/bpmn-js-cli, so the link needs access to that repo. It adds Zeebe, template, annotation and layout commands, per-command help, a filterable template listing and the runner. The specs, runs and scorer are in experiments/ai-agent-bpmn in the same repo.
