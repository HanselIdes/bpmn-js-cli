AI Agent BPMN Bake-off

Can an agent rebuild Camunda's "AI Agent Chat With Tools" process from a plain-language spec faster with a dedicated CLI than with a Python generator or the /camunda-bpmn skill? Python and /camunda-bpmn ran twice each. The CLI ran twice in each of six iterations, and the last iteration is shown. Every run passed lint and the tutorial's tests.

Blueprint
The tutorial's own diagram for this process. Every run is scored against it.
Closeness
A 0 to 100 match to the blueprint's structure, configuration, annotations and layout. It measures similarity to the blueprint, not whether the diagram works or reads well.
Gate
Lint with 0 errors plus the tutorial's 6 tests. Time to first passing gate is the clock from start to the first pass, without time queued behind other trials' test runs.
Auto layout
The CLI runner places the shapes itself, so a script works out no diagram coordinates.

Takeaways

/camunda-bpmn is the status quo: the agent writes the BPMN XML, including every diagram coordinate, following the skill's layout rules, and uses c8ctl to apply connector templates. A Python generator is the common fallback when no dedicated tool exists. Both are compared with the extended CLI, run with auto layout.

Notes

  • Where points were lost. All six runs share some differences from the blueprint: template defaults it lacks (followRedirects, documentReturnFormat, reasoning effort), ignoreNullValues on the GET tools, which template v18 does not offer, and FEEL written without parentheses. Other misses are method-specific: the four Python and /camunda-bpmn runs lack the agentDefinition element, which c8ctl v4.0.0 drops when it applies the AI Agent template (fixed in camunda/c8ctl#574), and the CLI runs have it. Shape positions differ from the blueprint by 89 to 178 px.
  • What the layout score shows. Both CLI runs score the same layout (9.5 of 15) because the auto layout is deterministic, so the score says little about the agent. It also measures how close shapes sit to the blueprint's positions, not overlaps or readability.
  • CLI gap the agents reported. With auto layout the tools are placed in creation order, so cli12 reordered its tool calls to get the left and right columns the spec asks for. Annotation 3 sits above the agent rather than below the user task.
  • Method. Closeness is an F1 over facts from both files, weighted structure 25, configuration 50, annotations 10, layout 15. Tokens are the subagent total reported by the harness.
  • The fork is branch camunda-executable of the private repo HanselIdes/bpmn-js-cli, so the link needs access to that repo. It adds Zeebe, template, annotation and layout commands, per-command help, a filterable template listing and the runner. The specs, runs and scorer are in experiments/ai-agent-bpmn in the same repo.
