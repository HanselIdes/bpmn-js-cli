AI Agent BPMN Bake-off

Can an agent rebuild Camunda's "AI Agent Chat With Tools" process from a plain-language spec faster with a dedicated CLI than with a Python generator or the /camunda-bpmn skill? Each method ran twice, and every run passed lint and the tutorial's tests.

Takeaways

The extended CLI, run with the runner's auto layout, measured against two baselines. /camunda-bpmn is the status quo: the agent writes the BPMN XML by hand with the skill, including every diagram coordinate, following its layout rules. A Python generator is in the comparison because it is what an agent tends to reach for by default when asked to produce a file from code.

Notes

  • Where points were lost. All six runs differ from the canonical file in the same ways: template defaults it lacks (followRedirects, documentReturnFormat, reasoning effort), ignoreNullValues on the GET tools, which template v18 does not offer, and FEEL written without parentheses. Shape positions differ by 89 to 178 px.
  • CLI gap the agents reported. With auto layout the tools are placed in creation order, so cli12 reordered its tool calls to get the left and right columns the spec asks for. Annotation 3 sits above the agent rather than below the user task. Earlier CLI rounds, including ones without auto layout, are in the repo and not shown here.
  • Method. Done gate: c8ctl bpmn lint with 0 errors, plus the tutorial's 6-scenario test suite. Closeness (0 to 100) is an F1 over facts from both files, weighted structure 25, configuration 50, annotations 10, layout 15. Tokens are the subagent total reported by the harness.
  • The fork is branch camunda-executable of the private repo HanselIdes/bpmn-js-cli. It adds Zeebe, template, annotation and layout commands, per-command help, a filterable template listing and the runner. The specs, runs and scorer are under experiments/ai-agent-bpmn.
